⚠ BREAKING CVE-2026-109618 CVE-2026-109619

Emergency PHP Patches Address Critical 'PHP2Shell' Flaws as In-the-Wild Exploitation Mounts

The PHP project released emergency security updates fixing two critical unauthenticated remote code execution vulnerabilities, dubbed PHP2Shell (CVE-2026-109618, CVE-2026-109619). Threat actors launched millions of exploit attempts attempting to deploy Mirai malware, while a subsequent unpatched RCE risk (CVE-2026-115560) emerged affecting non-default session serialization configurations.

📈 Impact: Unauthenticated attackers can achieve full remote code execution across any web server executing vulnerable PHP runtimes, with mod_php environments facing pre-execution arbitrary code execution. Exposure is runtime-level and independent of application frameworks or CMS plugins.

✅ Action: Upgrade immediately to PHP 8.5.12, 8.4.27, 8.3.36, or 8.2.35, and mitigate CVE-2026-115560 by setting session.upload_progress.enabled=0 in php.ini.

⚠ BREAKING

GitLab Issues Critical CVSS 10.0 Unauthenticated RCE Vulnerability Across All Self‑Managed Versions Since 2014

GitLab patched a CVE‑2026‑110264 flaw that enables unauthenticated remote code execution via an integer overflow in regular‑expression compilation. The vulnerability affects every self‑managed GitLab release from 7.0 (2014) through 19.5, requiring immediate upgrades to fixed versions.

📈 Impact: Security teams must treat this as a severe, exploitable flaw that could allow attackers to execute arbitrary code on any vulnerable GitLab server without credentials.

✅ Action: Upgrade all self‑managed GitLab instances to the fixed releases listed by GitLab (e.g., 19.5.1, 19.4.3, 19.3.6, 19.2.9, 19.1.9, 19.0.10, or 18.11.13) without delay.

⚠ BREAKING

Arista VeloCloud Orchestrator Zero‑Day (CVE‑2026‑114625) Actively Exploited, Critical Patch Released

Arista Networks confirmed that a critical‑severity SQL injection zero‑day (CVE‑2026‑114625) in VeloCloud Orchestrator (VCO) is being exploited in the wild. The flaw lets any authenticated user—including read‑only accounts—escalate to operator (superuser) privileges, compromising the confidentiality, integrity and availability of SD‑WAN management.

📈 Impact: Security teams must assume that any VCO deployment with vulnerable versions may have been fully compromised and that attackers can control the SD‑WAN fabric.

✅ Action: Deploy the patched VCO releases (5.2.3.18, 6.1.3.10, 6.4.2.12 or later), restrict web‑interface access to trusted networks, and monitor logs for suspicious activity and known malicious IPs.

📈 Impact: Security teams must treat all services that decode untrusted Brotli data as actively exploitable, because an attacker can achieve arbitrary code execution without custom builds or debuggers.
